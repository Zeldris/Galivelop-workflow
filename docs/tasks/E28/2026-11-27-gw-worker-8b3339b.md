# 2026-11-27 · gw-worker · pending · E28

## Why

Hallazgos A1 y B2 de `docs/records/security-review-E28.md`: `protectedBranch` llegaba a `git fetch origin <b>` como
argumento posicional (`--upload-pack=…` ejecutaba una orden) y `metrics.ledger` se escribía sin contener la ruta
(`../../.bashrc` o un `ledger.jsonl` enlazado recibían filas JSON).

## Alternatives

- Solo el esquema: basta para los scripts que leen el config con `config.load`, pero no defiende si un script lee el
  valor sin validar; por eso, además, `-` al principio se rechaza en el script y el fetch va con `--` y refspec
  explícito.
- Para el registro, contener también a los lectores (report, compare, alert): se deja fuera; leer no escribe fuera
  del repo y el esquema ya cierra la ruta.

## Changed because

El refspec explícito actualiza `origin/<b>` aunque el clon tenga un `remote.origin.fetch` estrecho. Un registro
rechazado en el gancho `Stop` da una línea `systemMessage` con el arreglo y sale con 0, como su contrato.
