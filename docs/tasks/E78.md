# E78 · `front.py run full --update-snapshots` y el sello de las capturas

## Goal

Que las capturas de las pruebas visuales se tomen y se sellen con una orden, no a mano: `run full` corre en una copia
temporal y no podía dejar capturas en el árbol, y el sello `front.snapshotStamp` se escribía a mano (Q-36).

## Scope

- `scripts/front.py`: `run full --update-snapshots` pasa `--update-snapshots` a Playwright (en Linux o en Docker),
  devuelve al árbol las capturas de `front.snapshotGlob` nuevas o cambiadas y escribe la versión fijada de Playwright en
  `front.snapshotStamp`. Solo tras un run correcto; nada se sube ni se hace commit.
- Falla con 2 si se pide con `run fast` o si `package.json` no fija una versión exacta (sin ella no hay sello).
- `doctor.py`: el arreglo de los avisos `front snapshots` nombra la orden nueva.
- Docs: `templates/front/README.md`, `docs/{es,en}/config.md`, descripción del esquema.
- Fuera: borrar capturas obsoletas o de otra plataforma (las borra el usuario; `doctor.py` avisa).

## Acceptance

- [x] Las capturas nuevas vuelven al árbol y el sello queda con la versión fijada, en Linux y en Docker (tests).
- [x] Tras un fallo, ni capturas ni sello; con `fast` o sin versión exacta, 2 con el motivo y sin correr nada.
- [x] `doctor.py` propone `front.py run full --update-snapshots`.
