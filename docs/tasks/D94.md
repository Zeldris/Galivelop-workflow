# D94 · `push.sh`: reintentos y éxito solo con `ls-remote`

## Goal

Que una subida se reintente ante fallos de red (`pushRetryDelays`) y solo se dé por hecha cuando `git ls-remote`
confirma el commit en `origin`, con un límite de tiempo por `ls-remote` (`pushLsRemoteTimeout`).

## Scope

`scripts/push.sh` y sus tests. Esta ficha nace en un arreglo posterior (2026-11-18): el límite de `ls-remote` medía
solo vueltas de `sleep 0.1`.

## Acceptance

- [x] Un `ls-remote` más lento que el límite se corta también en una máquina cargada: el tiempo real (`$SECONDS`)
  lo para además de las vueltas (`tests/test_push.py::PushSh`).

## Files

`scripts/push.sh`, `tests/test_push.py`.

## Change log

- 2026-11-18: el CI de macOS falló porque 10 vueltas de `sleep 0.1` tardaron más de 2 s y la respuesta lenta llegó
  antes del corte; ahora corta también el tiempo real.

## Verification

`python3 -B -m unittest discover -s tests -p 'test_push.py'`: 31 tests en verde en Linux; macOS, en el CI.
