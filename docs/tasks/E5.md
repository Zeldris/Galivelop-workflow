# E5 · Pruebas de front según la investigación

## Goal

Que un proyecto con front (Portal-Galivelop, World-Maker-Fantasy) tenga pruebas de front deterministas como las de
back, sin servicios de pago, siguiendo [`ref-front-testing.md`](../research/ref-front-testing.md) y las respuestas
E-9 a E-16 de [`E-quality.md`](../design/E-quality.md): las normas escritas se expresan como dato (tokens y
breakpoints) y un script del flujo genera de ahí las reglas de Stylelint y la matriz de viewports de Playwright.

## Decisiones (Q-31 a Q-35, usuario, 2026-11-21: «29. Si 30.a 31.a 32.ok 33. Ok»)

- **Q-31, alcance:** los tres trozos de abajo; E9-E16 se aplican dentro de E5 y se marcan hechas con ella; E7 (guía y
  plantilla de config) aparte, con `Related: E5`.
- **Q-32, tokens:** subconjunto del formato W3C Design Tokens (DTCG): grupos anidados, hojas con `$value` y `$type`,
  alias `{grupo.token}`.
- **Q-33, plantillas:** TypeScript.
- **Q-34, pruebas aquí:** proyecto de ejemplo en `tests/fixtures/front-sample` que el check corre con node y
  Playwright en Linux (sin node o en macOS, se omite con aviso); el generador, con tests en Python siempre.
- **Q-35, Stylelint:** `stylelint-declaration-strict-value` para colores, espaciados y tamaños de letra; versiones de
  Stylelint, Playwright y axe fijadas en la plantilla.

Ya cerradas (2026-11-01, E-9 a E-16): visual solo en Docker o Linux (macOS la omite con aviso); visual solo en el CI
y en la fase de cierre, el `pre-push` lleva Stylelint, layout y axe; tokens y breakpoints en un JSON enlazado desde
`gw.json`; CSS y SCSS; axe bloquea en grave o crítica, Lighthouse solo informa; capturas en git y en LFS por encima
de un umbral; sin servicios de pago; Chromium en todos los breakpoints, WebKit y Firefox solo en el escritorio y el
móvil principales.

## Scope

1. **Trozo 1 — dato y generador:** bloque `front` en `.claude/gw.json` (`tokens`: ruta al JSON, `null` = sin front;
   `out`: carpeta de lo generado; `breakpointGroup`; `mainBreakpoints`; `browsers`); `scripts/front.py check`
   valida el JSON (tipos admitidos, alias que resuelven y sin ciclos, breakpoints en `px`) y `front.py generate`
   escribe `tokens.css` (propiedades `--…`), `_tokens.scss`, `stylelint.tokens.json` (strict-value para colores,
   espaciados y tamaños de letra) y `playwright.projects.json` (cada breakpoint en Chromium; los principales también
   en WebKit y Firefox). Lo generado se declara en `generated` (E72) para que el check lo compare. Falla cerrado con la
   orden que lo arregla. `schema/gw.schema.json`, `templates/gw.json`, `docs/es|en/config.md`.
2. **Trozo 2 — plantillas de prueba:** `templates/front/` en TypeScript: `playwright.config.ts` que lee
   `playwright.projects.json`, fixture `stable()` (reducedMotion, `page.clock`, `fonts.ready`, red bloqueada,
   animaciones apagadas), helpers de layout (sin desborde, sin solape, objetivos táctiles) y de axe (grave o crítica
   bloquea), `.stylelintrc.json` que extiende lo generado, `package.json` con versiones fijadas; y
   `tests/fixtures/front-sample` que lo prueba (Q-34), con un caso rojo por helper.
3. **Trozo 3 — checks:** `front.py run fast|full` (fast: Stylelint, layout y axe en los breakpoints principales; full:
   además la visual y la matriz entera, solo en Linux o Docker, con aviso y salida distinta de cero si se pide en
   macOS sin Docker); el `pre-push` corre `fast` si hay `front.tokens`; el CI y la fase de cierre, `full`;
   `doctor.py` avisa de capturas `-darwin` o de otra versión de Playwright y de capturas por encima de
   `front.lfsThresholdKb` fuera de LFS.

## Acceptance

- [x] Un JSON de tokens con un alias roto, un ciclo, un `$type` no admitido o un breakpoint sin `px` hace fallar
  `front.py check` con el motivo y la orden (tests: `Check.test_broken_alias_fails_with_the_alias`, `test_cycle_fails`, `test_type_not_allowed_fails_with_the_type`, `test_breakpoint_without_px_fails`).
- [x] `front.py generate` es determinista (dos pasadas, mismos bytes) y da los cuatro archivos esperados para un
  ejemplo (tests: `Generate.test_two_runs_give_the_same_bytes`, `test_four_files_are_written`).
- [x] La matriz sale de E-16: cada breakpoint en Chromium y los principales en WebKit y Firefox (test: `Generate.test_matrix_follows_e16`).
- [x] Sin `front.tokens`, `front.py` no hace nada y sale en 0 (test: `NoFront.test_without_tokens_every_subcommand_does_nothing`).
- [x] El proyecto de ejemplo pasa en Linux con node; cada helper tiene un caso rojo que falla por su motivo (tests: `tests/test_front_sample.py`, `test_playwright_specs_pass_in_chromium` corre las 24 especificaciones por proyecto: un verde y un rojo con el mensaje por helper; `test_stylelint_rejects_a_literal_color`).
- [x] `run full` en macOS sin Docker no da verde falso (tests: `Run.test_full_on_macos_without_docker_refuses_with_the_reason` y `test_full_on_macos_with_docker_stopped_refuses_too` en `tests/test_front.py`; el `pre-push`, en `PrePushFront` de `tests/test_hooks.py`).
- [x] `doctor.py` avisa de capturas de otra plataforma y de capturas grandes fuera de LFS (tests: `test_front_snapshot_from_darwin_warns`, `test_front_snapshot_of_another_playwright_warns`, `test_front_large_snapshot_outside_lfs_warns_and_inside_lfs_does_not` en `tests/test_doctor.py`).
- [x] Copias generadas al día (`python3 scripts/apply.py .`), docs es/en, roadmap (E5 y E9-E16) y
  `bash tests/check.sh` en verde.
