# E7 · Guía de pruebas de front y CI de los proyectos con `front.py run full`

## Goal

Que un proyecto con `front.tokens` tenga en su CI las pruebas de front completas (visual y matriz entera, E-10) sin
copiar pasos a mano, y una guía que diga cómo montarlas de principio a fin (Q-29: aparte de E5; Q-35: el CI, dentro
de E7).

## Scope

1. `scripts/front.py install --matrix`: instala los navegadores de la matriz (`front.browsers.all` y `.main`, sin
   repetir), para que el CI no tenga que sacarlos del config con un script en línea. El CI de este repo lo usa.
2. `templates/github/check.yml`: el trabajo `versions` da `front=true|false` (con `front.tokens`); con `true`, el
   paso de node se monta aunque no haya `package.json` en `ciNodeDirs`, y tras «Check» un paso «Front» corre
   `front.py install --matrix --with-deps` y `front.py run full` (el runner es Linux). Sin `front.tokens`, el paso
   se salta. Solo se añaden líneas, así que `check.legacy-lines.txt` no cambia.
3. Guía en `docs/es/patterns.md` y `docs/en/patterns.md`: tokens, `front.dir` con la plantilla dentro (Q-36),
   `generate`, `pre-push` con `run fast`, CI y cierre con `run full`, capturas de referencia.
4. «Plantilla de config»: ya está (`front` en `templates/gw.json` y `templates/front/`, E5); nada nuevo.
