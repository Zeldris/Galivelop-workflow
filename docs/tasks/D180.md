# D180 · whole-read.py falla cerrado con wholeReadDenyPaths

## Goal

Barrido de los leves de `scripts/whole-read.py` en `pending.md` (E70, E74; retro de la `0.9.1`, P5). Decisión del usuario (Q-40, a): con `wholeReadDenyPaths` configurado, lo que el gancho no entiende y toca una ruta denegada se rechaza; todo lo demás sigue avisando y fallando abierto.

## Scope

- Un `Read` con `limit` igual o mayor que las líneas del fichero, desde el principio (`offset` ausente, 0 o 1), cuenta como lectura entera de una ruta denegada; un `limit` que no es un número entero o un fichero que no se puede contar, también.
- Un comando de Bash que `bash_reads` no sabe partir se rechaza si alguna de sus palabras es una ruta denegada (contra `cwd` o la raíz; un `cd` previo no se sigue).
- `AGENTS.md` apunta la excepción a «fallan cerrados»: los ganchos que solo aconsejan (`whole-read.py`, `other-repo-read.py`) fallan abiertos. Las plantillas no llevan esa regla.
- Fuera: rechazar claves como `/` o `../` en `config.py validate` (otra tarea).

## Acceptance

- [x] Comando sin partir que nombra una ruta denegada → rechazo con su motivo (`test_whole_read`, `Deny`).
- [x] Comando sin partir que no nombra ninguna, o sin `wholeReadDenyPaths` → pasa.
- [x] `limit` enorme sobre un fichero denegado → rechazo; `limit` parcial, `offset` posterior o `pages` → pasa.
- [x] Cada caso, rojo sin el arreglo (`red-without-fix.sh`).
