# A12 · Idiomas configurables en un bloque `languages`

## Goal

Que cada proyecto diga en `.claude/gw.json` en qué idioma va cada cosa (código, doc interna, doc pública, interfaz y
la conversación con el agente) en vez de una sola clave `language` y la regla fija de A8 (usuario, 2026-11-08).

## Decisiones (Q-10 a Q-16, usuario, 2026-11-20: «todo lo que recomiendas»)

- **Q-10:** una ficha, tres trozos: (1) esquema, lectura y migración; (2) consumidores; (3) idioma del agente.
- **Q-11:** forma, con códigos ISO 639-1:
  `"languages": {"code": "en", "docs": {"primary": "es", "others": ["en"]}, "public": {"primary": "en", "others": ["es"]}, "ui": []}`
  (la de este repo).
- **Q-12:** migración `schemaVersion` 1 → 2 en `MIGRATIONS` de `config.py` (en memoria para todo lector;
  `apply.py --update` la escribe): `language` → `docs.primary` y `public.primary`, `visibleLanguages` → `ui`,
  `code` = `"en"`, `docs.others` y `public.others` = `[]`. Un config sin migrar se sigue leyendo; `doctor.py` avisa
  de que está sin migrar, con la orden.
- **Q-13:** plantillas de `templates/<docs.primary>/`; si no hay carpeta para ese idioma, las de `en` y aviso de
  `doctor.py`.
- **Q-14:** commits (trailer `Siguiente:`/`Next:`, mensaje de `reviewed.sh`), bitácora, roadmap y textos de
  `handoff.py`, `merge-main.py`, `task.py`, `merge-branch.sh` y `backport.sh` siguen a `docs.primary`.
- **Q-15:** `names-check.py` solo comprueba con `code` = `en`; con otro valor se salta y lo dice.
- **Q-16:** idioma del agente por usuario en `~/.claude/gw.json`: `{"agentLanguage": {"<git config user.email>":
  "es"}}`; el gancho `SessionStart` imprime `Agent language: <x>` (respaldo: `docs.primary`); `CLAUDE.md` (y su
  plantilla) dejan de fijar el idioma y remiten a esa línea.

## Scope

1. **Trozo 1 — esquema:** `scripts/config.py` (`SCHEMA_VERSION` 2, `_migrate_to_2`, validación del bloque, un
   accesor de los idiomas para los lectores), `schema/gw.schema.json`, `templates/gw.json`, `.claude/gw.json` de este
   repo (forma de Q-11), `apply.py --init` (`--language` rellena `docs.primary` y `public.primary`;
   `--visible-language` rellena `ui`; flags nuevos `--code-language`, `--docs-language` y `--public-language`
   repetibles: el primero es el principal), `docs/es/config.md` ↔ `docs/en/config.md`.
2. **Trozo 2 — consumidores:** `apply.py` (plantillas y su `{{language}}`, respaldo `en`), `commit-message.py`,
   `reviewed.sh`, `merge-branch.sh`, `backport.sh`, `handoff.py`, `merge-main.py`, `task.py`, `doctor.py` (avisos de
   Q-12 y Q-13), `names-check.py` (Q-15), `templates/*/REVIEW.md` (`languages.ui`), el emparejado de
   `tests/test_repo.py` (lee `docs.primary` y `docs.others`), skills que nombran `language` (`gw-doctor`, `gw-init`,
   `gw-selector`) y la guía de `gw-init`.
3. **Trozo 3 — idioma del agente:** `scripts/session-start.sh` (o el script que llama) lee `~/.claude/gw.json` con
   el email de `git config user.email`; `templates/*/CLAUDE.md` y `CLAUDE.md` de este repo remiten a la línea;
   `docs/es/config.md` ↔ `en` explican el archivo de usuario.

## Acceptance

- [ ] Un config con `language`/`visibleLanguages` se lee migrado (`config.py get languages.docs.primary`) y
  `apply.py --update` lo escribe en schema 2; test de la migración y de un bloque inválido (motivo comprobado).
- [ ] Cada consumidor del trozo 2 lee `docs.primary`; un idioma sin plantillas usa `en` y `doctor.py` avisa (tests).
- [ ] `names-check.py` con `code` ≠ `en` se salta y lo dice (test).
- [ ] El gancho de inicio imprime `Agent language: es` con el archivo de usuario y `docs.primary` sin él (tests).
- [ ] Copias generadas al día (`python3 scripts/apply.py .`) y `bash tests/check.sh` en verde.
