# 2026-11-18 · gw-worker · pending · C4

## Why

Arreglos de la revisión de C4/C5 (decisiones de la sesión principal). La raíz sale de `config.find_root()` para que
funcione la instalación por plugin. Las preguntas se leen del worktree principal, porque ahí apunta la sesión principal
las de los subagentes (C10), y las órdenes llevan `--root`. `accept-risk` y `task.py current <id>|--clear` piden
confirmación al usuario en `config-guard.py`. Un `gw.json` roto bloquea el código, salvo el propio `gw.json`. Se
clasifica antes que nada: la documentación, `content` y el archivo de preguntas se editan siempre. `task.py new` marca la
tarea aunque la ficha exista y `close-row <id>` borra la marca. La ruta se resuelve con `realpath` y, si hace falta, con
`samefile`. Las llamadas a git tienen límite de tiempo (`task.GIT_TIMEOUT`), y si git se cuelga el modo restrictivo
bloquea.

## Alternatives

Con un `gw.json` roto, bloquear solo si hay tarea en curso: no se sabe leer el `taskId` sin config. Para el límite de
git, una clave nueva en `gw.json`: se dejó una constante como `GIT_TIMEOUT` de `config-guard.py`.
